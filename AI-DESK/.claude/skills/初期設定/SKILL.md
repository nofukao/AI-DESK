# 初期設定 — 対話で PROFILE.md と読み取り範囲を整える

新しい AI-DESK には、次の2つが足りません。**どちらも、この手順で作れます。**

| 作るもの | 中身 | 無いとどうなるか |
|---|---|---|
| `PROFILE.md` | この組織の前提知識（業態・社内の言葉・資料の場所） | 依頼のたびに確認が増える。**動かないわけではない** |
| `.claude\settings.local.json` | 読んでよいフォルダ | **この AI-DESK の中しか読めない** |

**両方まとめてやる必要はありません。** ユーザーが困っているほうから始めてください。
「資料が読めない」なら 2 から、「会社のことを教えたい」なら 1 からです。

## 進め方の原則（最初に読むこと）

- **白紙から質問攻めにしない。** 調べられることは先に調べ、**下書きを見せてから確認**する
- **質問は一度に1つ。** 「どちらですか」と選べる形にする（PC に不慣れな人が相手です）
- **分からなければ飛ばしてよい**と、最初に伝える。全部埋める必要はありません
- **推測で埋めない。** 聞いていないことは書かない。曖昧なものは「未確認」と書く
- **短く書く。** 間違った長い `PROFILE.md` より、正しい短いもののほうが役に立ちます

# 1. `PROFILE.md` を作る

## 1-0. まず状態を見分ける

| 状態 | 見分け方 | どうするか |
|---|---|---|
| **無い** | `PROFILE.md` が存在しない | この手順で作る |
| **記入例のまま** | 中に `AI-DESK-PROFILE-EXAMPLE` の行がある | **中身を事実として扱わない。** 作り直す |
| **白紙運用** | 中に `AI-DESK-PROFILE-NONE` の行がある | **そういう運用だと選ばれています。** 頼まれない限り作らない |
| **記入済み** | 上のどれでもない | 作り直さない。**直したい箇所だけ**を聞く |

## 1-1. 何をするかを伝える

> この AI-DESK に、あなたの組織のことを覚えてもらいます。
> 業態、社内でしか通じない言葉、資料がどこにあるか —— この3つが中心です。
> **分からないところは飛ばして構いません。** あとから何度でも足せます。
>
> **「いまはいい」「要らない」でも構いません。** そのまま作業できます。

### 「要らない」と言われたら

**食い下がらないでください。** 次の2つを区別します。

- **「いまはいい」「あとで」** → **何も書かない。** そのまま本来の作業に移る
- **「要らない」「白紙でいい」** → 下の内容で `PROFILE.md` を書き、**以後は聞かない**

```markdown
<!-- AI-DESK-PROFILE-NONE: この AI-DESK は、組織固有の前提知識を登録しない運用です -->

# PROFILE.md（白紙運用）

この AI-DESK では、組織固有の前提知識を登録しない運用にしています。

必要になったら「**初期設定**」と言ってください。対話で作れます。
```

## 1-2. 聞くこと（この順番で）

**1つずつ聞いてください。** 答えを聞いたら、次に進みます。

| # | 聞くこと | 質問の例 |
|---|---|---|
| 1 | 業態 | 「この組織は、主にどんな仕事をしていますか。一言で構いません」 |
| 2 | 依頼の中心 | 「AI に頼みたいのは、どんな仕事が多そうですか」 |
| 3 | 社内の言葉 | 「社内でしか通じない言い方や略語はありますか。例えば『あれ』で通じるようなもの」 |
| 4 | 資料の場所 | **下書きを見せてから聞く**（1-3 参照） |
| 5 | 記号の約束 | 「ファイル名やフォルダ名に、決まった付け方はありますか」 |
| 6 | 昔の場所 | 「フォルダの場所が変わったことはありますか。古い記録に昔の場所が書いてあると、読み替えが要ります」 |
| 7 | 毎回言っていること | 「AI に毎回言うことになりそうな注意はありますか。例えば金額は税抜で、個人名は伏せて、など」 |

**3 が最も効きます。** 社内用語は、AI が資料を読み違える最大の原因です。
思いつかないと言われたら、「では作業中に見つけたら足しましょう」と言って先へ進んでください。

## 1-3. 資料の場所は、下書きを見せてから聞く

**ここだけは、白紙で聞かないでください。**

1. `.claude\settings.local.json` があれば、`additionalDirectories` の一覧を読む
2. **そのフォルダの中を実際に一覧し**、何が入っていそうかを見る
3. **表の形にして見せてから**、「これで合っていますか。説明を足したいものはありますか」と聞く

```markdown
| パス | 内容 |
|---|---|
| `Z:\<フォルダ名>` | （ここに説明を入れてもらう） |
```

まだ読み取り範囲が設定されていない場合は、**先に 2 をやってください。**

## 1-4. 書く

`PROFILE.example.md` の節の構成に合わせて `PROFILE.md` を書きます。

- **`AI-DESK-PROFILE-EXAMPLE` の行は書き写さないこと**（記入例の目印です）
- 架空の会社（サンプル商事）の内容は**1文字も残さない**
- **聞けなかった節は、節ごと省いてよい。** 空の節を並べない
- 末尾に、次の1行を必ず入れる

```markdown
> この内容は、AI が対話で作成しました。**間違いを見つけたら直してください。**
> このファイルは自由に書き換えられます（配布物ではありません）。
```

書いたら、**要点をチャットで示して**「直したいところはありますか」と聞いてください。
ファイルを開かせないこと。

## 1-5. 伝えること

- `PROFILE.md` は**このインスタンスだけのもの**です。配布されません
- **次の起動から効きます**（規則と前提知識は、起動したときに読み込まれます）
- 足りないと気づいたら、**いつでも「PROFILE に足して」と言えます**

# 2. 読んでよいフォルダを決める（`.claude\settings.local.json`）

## 2-0. 【重要】この節の規則

**このファイルで、AI が触ってよいのは `additionalDirectories` だけです。**

`.claude\` の中は Claude Code が特に守っている場所なので、Auto モードでも書き込みの前に
安全チェックが入り、**確認が出ることがあります。** 確認が出たら、何を書くのかをユーザーに説明してください。

- **`deny` の節に手を触れないこと。** ここは、業務フォルダへの書き込みを塞いでいる歯止めです
- **読める場所を足すときは、そのドライブへの書き込みを塞ぐ `Edit` の deny も足すこと**
  （同じドライブの deny が既にあれば、足す必要はありません）

> **読んでよい場所は、書いてはいけない場所でもある。**

この対応が崩れると、**資料フォルダに書き込めてしまいます。**
`疎通確認` が毎回この対応を検査しますが、**崩さないのはあなたの責任**です。

## 2-1. 何があるかを見せてから、選んでもらう

**パスを打たせないでください。** 一覧して、選んでもらいます。

```powershell
Get-ChildItem "Z:\" -Directory | Select-Object -ExpandProperty Name
```

ドライブが分からなければ、まず「資料は、どのドライブに入っていますか（`Z:` など）」と聞きます。
分からないと言われたら、`Get-PSDrive -PSProvider FileSystem` の結果を見せて選んでもらいます。

そのうえで **「この中の、どれを読めるようにしますか」** と聞きます。

## 2-2. 範囲は狭くする

**「全部でいい」と言われても、そのまま全部にしないでください。** 次を伝えます。

> ドライブ全体を対象にすると、**検索が終わらなくなることがあります**（ファイルが多すぎるためです）。
> それに、範囲は狭いほど安全です。**よく使うフォルダをいくつか**挙げませんか。

そのうえで、なお全体を希望されたら、**その希望に従って構いません。**
そのときは「検索するときはフォルダを指定してください」と添えてください。

## 2-3. 書く

```json
{
  "permissions": {
    "additionalDirectories": [
      "Z:/<選ばれたフォルダ1>",
      "Z:/<選ばれたフォルダ2>"
    ],
    "deny": [
      "Edit(//z/**)"
    ]
  }
}
```

- **区切りは `/`（スラッシュ）です。** `\` と書くと効きません。ここだけの決まりです
- **`deny` は、選ばれた場所を含むドライブごとに書きます。**
  別のドライブ（`Y:` など）が加わったら、`Edit(//y/**)` も足します
- **deny のドライブは、必ず `Edit(//z/**)` の形で書きます。**
  `Edit(Z:/**)` と書くと**効きません**。Windows のパスは、照合の前に `/z/...` の形
  （ドライブ文字は小文字、先頭に `/`）に直されるためです。先頭の `//` が「ドライブの根から」を表します
- **`Write(...)` は書かないこと。** ファイルの書き込みは `Edit(...)` だけで判定され、
  `Write(...)` は参照されません（起動時に警告が出ます）
- 既にファイルがある場合は、**`additionalDirectories` に足すだけ**にしてください。
  既存の `deny` を消さないこと

## 2-4. 伝えること（ここが一番忘れられます）

> **claude をいったん終了して、起動し直してください。**
> 読み取り範囲は、起動したときに読み込まれます。**このままでは、まだ読めません。**
>
> 起動し直したら「**疎通確認**」と言ってください。実際に読めるか確かめます。

**同じセッションで「読めるようになったか試す」ことはできません。** 試したふりをしないでください。

# 3. 最後に

両方が済んだら、次を案内して終わります。

1. **claude を起動し直す**
2. **`疎通確認`** と言って、読み取り範囲と書き込み制限を確かめる
3. 依頼の仕方は `README.md` と `task_template\Readme.md` にある

**この手順でファイルを作れなかった場合**（確認を断られた、書き込みが拒否された）は、
**そのまま報告してください。** 勝手に別の場所へ書いたり、内容を `out\` に出したりしないこと。
手で作る手順は `README.md` に書いてあります。
