# 初期設定 — 対話で PROFILE.md を作る

新しい AI-DESK には、**`PROFILE.md`（この組織の前提知識）がありません。** この手順で作ります。

| 作るもの | 中身 | 無いとどうなるか |
|---|---|---|
| `PROFILE.md` | この組織の前提知識（業態・社内の言葉・資料の場所・AI に読ませない場所） | 依頼のたびに確認が増える。**動かないわけではない** |

**読んでよいフォルダの設定は、要りません。** 資料は、依頼ごとに必要なところを読みます。
書き込める場所は、最初から決まっています（`<タスクフォルダ>\` の中など。→ `CLAUDE.md` 絶対遵守ルール1）。

**この手順で、`.claude\` の中の設定ファイルを作ったり書き換えたりしないでください。**
（書こうとしても、書き込みの制限で止まります）

## 進め方の原則（最初に読むこと）

- **白紙から質問攻めにしない。** 調べられることは先に調べ、**下書きを見せてから確認**する
- **質問は一度に1つ。** 「どちらですか」と選べる形にする（PC に不慣れな人が相手です）
- **分からなければ飛ばしてよい**と、最初に伝える。全部埋める必要はありません
- **推測で埋めない。** 聞いていないことは書かない。曖昧なものは「未確認」と書く
- **短く書く。** 間違った長い `PROFILE.md` より、正しい短いもののほうが役に立ちます

## 1. まず状態を見分ける

| 状態 | 見分け方 | どうするか |
|---|---|---|
| **無い** | `PROFILE.md` が存在しない | この手順で作る |
| **記入例のまま** | 中に `AI-DESK-PROFILE-EXAMPLE` の行がある | **中身を事実として扱わない。** 作り直す |
| **白紙運用** | 中に `AI-DESK-PROFILE-NONE` の行がある | **そういう運用だと選ばれています。** 頼まれない限り作らない |
| **記入済み** | 上のどれでもない | 作り直さない。**直したい箇所だけ**を聞く |

## 2. 何をするかを伝える

> この AI-DESK に、あなたの組織のことを覚えてもらいます。
> 業態、社内でしか通じない言葉、資料がどこにあるか —— この3つが中心です。
> **分からないところは飛ばして構いません。** あとから何度でも足せます。
>
> **「いまはいい」「要らない」でも構いません。** そのまま作業できます。

### 「要らない」と言われたら

**食い下がらないでください。** 次の2つを区別します。

- **「いまはいい」「あとで」** → **何も書かない。** そのまま本来の作業に移る
- **「要らない」「白紙でいい」** → 下の内容で `PROFILE.md` を書き、**以後は聞かない**

```markdown
<!-- AI-DESK-PROFILE-NONE: この AI-DESK は、組織固有の前提知識を登録しない運用です -->

# PROFILE.md（白紙運用）

この AI-DESK では、組織固有の前提知識を登録しない運用にしています。

必要になったら「**初期設定**」と言ってください。対話で作れます。
```

## 3. 聞くこと（この順番で）

**1つずつ聞いてください。** 答えを聞いたら、次に進みます。

| # | 聞くこと | 質問の例 |
|---|---|---|
| 1 | 業態 | 「この組織は、主にどんな仕事をしていますか。一言で構いません」 |
| 2 | 依頼の中心 | 「AI に頼みたいのは、どんな仕事が多そうですか」 |
| 3 | 社内の言葉 | 「社内でしか通じない言い方や略語はありますか。例えば『あれ』で通じるようなもの」 |
| 4 | 資料の場所 | **下書きを見せてから聞く**（4 参照） |
| 5 | AI に読ませない場所 | **無ければ飛ばす**（5 参照） |
| 6 | 記号の約束 | 「ファイル名やフォルダ名に、決まった付け方はありますか」 |
| 7 | 昔の場所 | 「フォルダの場所が変わったことはありますか。古い記録に昔の場所が書いてあると、読み替えが要ります」 |
| 8 | 毎回言っていること | 「AI に毎回言うことになりそうな注意はありますか。例えば金額は税抜で、個人名は伏せて、など」 |

**3 が最も効きます。** 社内用語は、AI が資料を読み違える最大の原因です。
思いつかないと言われたら、「では作業中に見つけたら足しましょう」と言って先へ進んでください。

## 4. 資料の場所は、下書きを見せてから聞く

**ここだけは、白紙で聞かないでください。パスを打たせないでください。**

1. 「資料は、どのドライブに入っていますか（`Z:` など）」と聞く。
   分からないと言われたら、次の結果を見せて選んでもらう
   ```powershell
   Get-PSDrive -PSProvider FileSystem
   ```
2. **そのドライブの中を実際に一覧し**、何が入っていそうかを見る
   ```powershell
   Get-ChildItem "Z:\" -Directory | Select-Object -ExpandProperty Name
   ```
3. **表の形にして見せてから**、「これで合っていますか。説明を足したいものはありますか」と聞く

```markdown
| パス | 内容 |
|---|---|
| `Z:\<フォルダ名>` | （ここに説明を入れてもらう） |
```

**一覧するのはフォルダ名までです。** 中のファイルを開いて読まないでください。

> 【Claude Code のみ】AI-DESK の外を**初めて**読むとき、Claude Code が
> 「この先も読み続けてよいか」を確認することがあります。**「Keep allowing」を選んでもらってください。**
> 「Block from now on」を選ぶと、**この PC のすべての作業で、AI-DESK の外を読めなくなります。**

## 5. AI に読ませない場所（任意）

**必須ではありません。** 次のように1回だけ聞き、無ければそのまま先へ進みます。

> 人は開けても、AI には読ませたくないフォルダはありますか。人事や給与の資料など。
> **無ければ「無い」で構いません。**

- **無い** → **この節は `PROFILE.md` に書かない**
- **ある** → パスと理由を聞いて、`PROFILE.md` に「AI に読ませない場所」の節を書く
  （4 の一覧から選んでもらって構いません）

あったときは、次のことを必ず伝えてください。

> AI は、ここに書いた場所を開きません。依頼で必要になりそうなときは、開く前にお聞きします。
> **ただし、これは AI への約束です。機械的に読めなくする設定ではありません。**

## 6. 書く

`PROFILE.example.md` の節の構成に合わせて `PROFILE.md` を書きます。

- **`AI-DESK-PROFILE-EXAMPLE` の行は書き写さないこと**（記入例の目印です）
- 架空の会社（サンプル商事）の内容は**1文字も残さない**
- **聞けなかった節は、節ごと省いてよい。** 空の節を並べない
- 末尾に、次の1行を必ず入れる

```markdown
> この内容は、AI が対話で作成しました。**間違いを見つけたら直してください。**
> このファイルは自由に書き換えられます（配布物ではありません）。
```

書いたら、**要点をチャットで示して**「直したいところはありますか」と聞いてください。
ファイルを開かせないこと。

## 7. 伝えること

- `PROFILE.md` は**このインスタンスだけのもの**です。配布されません
- **次に起動したときから、自動で読み込まれます。** このまま続けて作業する場合は、いま聞いた内容で進めます
- 足りないと気づいたら、**いつでも「PROFILE に足して」と言えます**

## 8. 最後に

次を案内して終わります。

1. **`疎通確認`** と言って、環境と書き込みの制限を確かめる
2. 依頼の仕方は `README.md` と `00_タスクテンプレート\README.md` にある

**この手順でファイルを作れなかった場合**（確認を断られた、書き込みが止められた）は、
**そのまま報告してください。** 勝手に別の場所へ書いたり、内容をタスクフォルダに出したりしないこと。
手で作る手順は `README.md` に書いてあります。
