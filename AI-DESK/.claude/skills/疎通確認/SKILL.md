# 疎通確認 — 作業環境の点検

この AI-DESK のインスタンスが正しく動いているかを、上から順に確認して報告してください。
**業務データには一切書き込まないこと。** 書き込みを試すのは、8 で作る点検用のタスクフォルダだけです。

## 1. ここがインスタンスのルートか

カレントディレクトリに **`.ai-desk\VERSION`** があるか確認し、**版番号**を読む。

- **ある** → そのフルパスと版番号を報告する（例: 「`C:\Users\yamada\AI-DESK`、版 1.0.0」）
- **無い** → ここは AI-DESK のインスタンスではない。**その旨を伝えて点検を中止する。**
  AI-DESK のフォルダに移動して起動し直すよう案内する

**この2つ（フルパスと版番号）は、他がすべて正常でも必ず報告してください。**

## 2. 配布元と版がずれていないか

`.ai-desk\source.txt` を読む。ここには、このインスタンスが**どこからコピーされたか**が
1行で書かれています。そのフォルダの `.ai-desk\VERSION` を読み、自分の版と比べる。

| 結果 | 報告のしかた |
|---|---|
| 同じ | 「最新です（版 X.Y.Z）」 |
| 配布元のほうが新しい | 「**このインスタンスは版 X.Y.Z です。配布元は版 A.B.C です。更新できます**」と伝え、管理者に `update-instance.ps1` での更新を依頼するよう案内する |
| 自分のほうが新しい | そのまま事実を報告する（配布元が古いままの可能性がある） |
| `source.txt` が無い | 「**配布元が記録されていないため、確認できませんでした**」 |
| 配布元に届かない（NAS に繋がっていない、移動した） | 「**配布元 `<パス>` に届かないため、確認できませんでした**」 |

**届かないことは失敗ではありません。** 「確認できませんでした」と正直に報告してください。
勝手に他の場所を探し回らないでください。

## 3. 規則を読めているか

`CLAUDE.md` を読み、冒頭の「役割と目的」が取得できるか確認する。

## 4. この組織の前提知識があるか

`PROFILE.md` の状態を、次の4つで見分けて報告する。

| 状態 | 見分け方 | 報告のしかた |
|---|---|---|
| **記入済み** | 下のどれでもない | 正常 |
| **無い** | ファイルが無い | 「**未設定です。**『初期設定』と言えば対話で作れます」 |
| **記入例のまま** | `AI-DESK-PROFILE-EXAMPLE` の行がある | 「**記入例のままです。中身は架空の会社の情報なので、いまは使えません。**『初期設定』と言えば対話で作れます」 |
| **白紙運用** | `AI-DESK-PROFILE-NONE` の行がある | 「白紙運用（そう選ばれています）」 |

**いずれも不具合ではありません。** 無くても規則はすべて有効であることを添えること。
ただし**「記入例のまま」は、放っておくと間違いのもと**なので、はっきり伝えてください。

## 5. 共通スキルが読み込まれているか

このスキル（疎通確認）自体が呼び出せている時点で、`.claude\skills\` は有効です。
**「有効」と報告してください。**

あわせて `.claude\skills\` の一覧を見て、**配布物の2つ（`疎通確認`・`継続タスク`）以外に
このインスタンスで足されたスキルがあれば、その名前を報告**してください。
（更新のときに上書きされないもの＝この環境の財産です）

## 6. 資料を読めるか（読み取り範囲と、信頼ダイアログの確認）

`.claude\settings.local.json` を読み、`permissions.additionalDirectories` の一覧を取り出す。

- **ファイルが無い** → 「**読んでよいフォルダが、まだ設定されていません。**
  いまは、この AI-DESK の中しか読めません。
  『**初期設定**』と言えば、対話で決められます」と案内する
- **ある** → **その一覧をユーザーに見せる。** さらに、そのうち1つに対して
  Glob などの内蔵検索をかけ、ファイルを列挙できるか確かめる
  - 列挙できた → 正常。**どのフォルダで試したかを書く**
  - 権限エラーになった → **信頼ダイアログが未承諾**の可能性が高い。次を案内すること。
    「Claude Code をこのフォルダで対話モードで一度起動し、
    『このフォルダを信頼しますか』の確認に承諾してください。
    承諾しないと settings.json の設定がすべて無視されます。」

### 6-2. 【重要】読める場所が、書けないようになっているか

**これは、この点検で最も大事な検査の1つです。**

`settings.local.json` の `additionalDirectories` に挙がっている場所は、
**すべて `deny` で書き込みを塞がれていなければなりません。**

> **読んでよい場所は、書いてはいけない場所でもある。**

一覧のそれぞれについて、そのドライブ（または、その場所を含む範囲）に対する
**`Edit(...)` の deny があるか**を確かめてください。

```json
"additionalDirectories": [ "Z:/03_XXXX" ]     ← 読める
"deny": [ "Edit(//z/**)" ]                  ← 対になる書き込み禁止
```

| 結果 | 判定 |
|---|---|
| すべて対になっている | 正常 |
| **対になっていないものがある** | **異常。** どの場所が無防備かを具体的に挙げて報告する |
| **deny が `Edit(Z:/**)` の形で書かれている** | **異常。** その書き方は Z: に当たらず、効いていません。`Edit(//z/**)` の形に直すよう伝える |
| **deny が `Write(...)` だけで書かれている** | **異常。** `Write(...)` は参照されません。`Edit(...)` に直すよう伝える |

**異常だった場合、あなたが `settings.local.json` を直してはいけません。**
`deny` の節は、あなたを縛っている歯止めです。
**どの行が足りないかを示して、ユーザーに手で直してもらってください。**

## 7. Python が使えるか

**`python` ではなく `py` を使い、ライブラリまで確かめる。**

```powershell
py -c "import sys, openpyxl, pandas, docx, pptx, pdfplumber; print(sys.executable)"
```

- **実体のパスが返った → 正常。** そのパスを報告する
- **エラー → 使えない。** 次のどちらかを切り分ける
  - `py` が無い、または Python 本体が無い → **導入の可否をユーザーに確認したうえで**
    `powershell -NoProfile -ExecutionPolicy Bypass -File "<インスタンスのルート>\bin\setup_python.ps1"`
    を実行し、**終了後に Claude Code の再起動を案内する**
  - Python はあるがライブラリが足りない → **確認不要。** `py -m pip install` で入れる

### 7-2. `python` が何を指しているか（警告のための確認）

```powershell
where python
```

返ってきたパスを見て、**次のどちらかなら警告してください。**

| 見つかったもの | 何が問題か |
|---|---|
| パスに `WindowsApps` を含む | Microsoft Store の誘導用スタブ（偽物）。実行しても動かない |
| **別アプリに同梱された Python**（`Inkscape`、`GIMP`、`Blender` などのフォルダの下） | 抽出ライブラリが入っておらず、**そこへ `pip install` すると他アプリの環境を壊す** |

どちらかだった場合は、
**「`python` は別物を指しています。`py` を使ってください」とユーザーに伝えてください。**
`python` が正規の Python を指していた場合も、**`py` を使う方針は変わりません**
（PC ごとに違うためです）。

**7 と 7-2 は別の確認です。** 7 が正常でも 7-2 の警告は出しうるので、両方報告してください。

## 8. 書き込みの制限が効いているか

**ここは「書ける」ことと「書けない」ことの両方を確かめる項目です。**

### 8-1. タスクフォルダの `out` に書けるか

点検用のタスクフォルダ `00_疎通確認` を使い、
**`00_疎通確認\out\00_点検記録.md`** に、この点検の日付と結果の要約を書いてください。

- フォルダが無ければ作ってかまいません（`00_疎通確認\out\` まで）
- **業務のタスクフォルダと区別するため、名前の頭は `00_` です。** 変えないでください
- **毎回このファイルを上書きします。** 番号を増やさないでください。点検の記録は1つで足ります
- 書けた → 正常
- **書けなかった → 異常。** `settings.json` の `deny` が広すぎる可能性があります。
  **ルート直下の `out` を塞ぐ deny が、タスクフォルダの `out` にまで当たっていないか**を疑い、
  （`Edit(/out/**)` のように先頭が `/` なら、ルート直下だけに当たります。
  `Edit(out/**)` や `Edit(./out/**)` だと、deny では深さを問わず当たり、すべての `out` が塞がれます）
  そのまま報告してください（これが起きると、この AI-DESK は何も出力できません）

### 8-2. ルート直下の `out` が拒否されるか

**これは「拒否されること」を確かめる項目です。**

この AI-DESK は既定で「自動」モードで動くため、**確認プロンプトは歯止めになりません。**
ここで効くのは `settings.json` の **`deny`** です。`deny` はモードに関係なく拒否します。

試す前に、**必ず次のようにユーザーに伝えてください。**

> これから、わざと間違った場所（インスタンスのルート直下の `out\`）へ書き込もうとします。
> **拒否されるのが正しい動作です。** 万一、確認が出た場合は「いいえ」と答えてください。

そのうえで、ルート直下の `out\点検.txt` を作ろうとしてください。

| 起きたこと | 判定 |
|---|---|
| **`deny` で拒否された**（確認も出ない） | **正常。** 歯止めが効いています |
| 確認プロンプトが出て、ユーザーが断った | **正常。** ただし権限モードが「自動」でない状態です |
| **書けてしまった** | **異常。** すぐに報告すること |

**「異常」の場合に疑うこと**を、順に挙げてください。

1. `.claude\settings.json` の `deny` に `Edit(/out/**)` があるか
2. 信頼ダイアログ（「このフォルダを信頼しますか」）に承諾しているか
3. 権限モードが `bypassPermissions` になっていないか

**書けてしまった場合、そのファイルを自分で消さないでください**（絶対遵守ルール4）。
どこに何を作ってしまったかを正確に報告し、ユーザーに削除を依頼してください。

## 9. インスタンスの構成

カレントディレクトリ直下に次があるか確認する。無いものは指摘する。

- `CLAUDE.md`
- `GEMINI.md`
- `.claude\settings.json`（`permissions.allow` に `Edit(*/out/**)` があるか）
- `task_template\`
- `bin\`

不足していれば、**管理者に更新を依頼するよう案内する**（AI が勝手にコピーしない）。

あわせて、**インスタンスの中に `.git` が無いこと**を確認する。
**あった場合は異常**として報告すること。インスタンスは Git のクローンではありません
（→ `CLAUDE.md` 絶対遵守ルール2）。
