# 疎通確認 — 作業環境の点検

この AI-DESK のインスタンスが正しく動いているかを、上から順に確認して報告してください。
**業務データには一切書き込まないこと。** 書き込みを試すのは、8 で使う点検用のタスクフォルダ `00_疎通確認` だけです。

## 1. ここがインスタンスのルートか

カレントディレクトリに **`.ai-desk\VERSION`** があるか確認し、**版番号**を読む。

- **ある** → そのフルパスと版番号を報告する（例: 「`C:\Users\yamada\AI-DESK`、版 1.1.0」）
- **無い** → ここは AI-DESK のインスタンスではない。**その旨を伝えて点検を中止する。**
  AI-DESK のフォルダに移動して起動し直すよう案内する

**この2つ（フルパスと版番号）は、他がすべて正常でも必ず報告してください。**

## 1-2. Windows で動いているか

**AI-DESK は Windows 専用です。** あなたの実行環境の情報（OS・プラットフォーム）を見て、Windows かどうかを確かめる。
分からなければ、シェルで確かめてよい（PowerShell なら `$env:OS`、それ以外なら `uname`）。

| 結果 | 判定と案内 |
|---|---|
| Windows | 正常 |
| **Windows 以外**（macOS・Linux など） | **異常。** 次のように、はっきり伝える |

> この AI-DESK は Windows 専用です。いまは Windows 以外の環境で開かれています。
> **書き込みの制限（hook）は Windows の PowerShell で動くため、ここでは動きません。
> 止まるのではなく、制限なしで書けてしまいます。**
> 業務には使わず、Windows の PC で開き直してください。

Windows 以外だった場合も、点検は最後まで続けてください（8-4 も素通りするはずです）。
**報告では、他がすべて正常でも「異常」と明記してください。**

## 2. 配布元と版がずれていないか

`.ai-desk\source.txt` を読む。ここには、このインスタンスが**どこからコピーされたか**が
1行で書かれています。そのフォルダの `.ai-desk\VERSION` を読み、自分の版と比べる。

| 結果 | 報告のしかた |
|---|---|
| 同じ | 「最新です（版 X.Y.Z）」 |
| 配布元のほうが新しい | 「**このインスタンスは版 X.Y.Z です。配布元は版 A.B.C です。更新できます**」と伝え、管理者に `update-instance.ps1` での更新を依頼するよう案内する |
| 自分のほうが新しい | そのまま事実を報告する（配布元が古いままの可能性がある） |
| `source.txt` が無い | 「**配布元が記録されていないため、確認できませんでした**」 |
| 配布元に届かない（NAS に繋がっていない、移動した） | 「**配布元 `<パス>` に届かないため、確認できませんでした**」 |

**届かないことは失敗ではありません。** 「確認できませんでした」と正直に報告してください。
勝手に他の場所を探し回らないでください。

## 3. 規則を読めているか

`CLAUDE.md` を読み、冒頭の「役割と目的」が取得できるか確認する。

## 4. この組織の前提知識があるか

`PROFILE.md` の状態を、次の4つで見分けて報告する。

| 状態 | 見分け方 | 報告のしかた |
|---|---|---|
| **記入済み** | 下のどれでもない | 正常 |
| **無い** | ファイルが無い | 「**未設定です。**『初期設定』と言えば対話で作れます」 |
| **記入例のまま** | `AI-DESK-PROFILE-EXAMPLE` の行がある | 「**記入例のままです。中身は架空の会社の情報なので、いまは使えません。**『初期設定』と言えば対話で作れます」 |
| **白紙運用** | `AI-DESK-PROFILE-NONE` の行がある | 「白紙運用（そう選ばれています）」 |

**いずれも不具合ではありません。** 無くても規則はすべて有効であることを添えること。
ただし**「記入例のまま」は、放っておくと間違いのもと**なので、はっきり伝えてください。

## 5. 共通スキルが読み込まれているか

このスキル（疎通確認）自体が呼び出せている時点で、`.claude\skills\` は有効です。
**「有効」と報告してください。**

あわせて `.claude\skills\` の一覧を見て、**配布物の4つ（`初期設定`・`疎通確認`・`新規タスク`・`継続タスク`）以外に
このインスタンスで足されたスキルがあれば、その名前を報告**してください。
（更新のときに上書きされないもの＝この環境の財産です）

## 6. 資料を読めるか

**読んでよいフォルダの設定はありません。** 資料は、依頼ごとに必要なところを読みます。
ここでは、**資料のあるフォルダを、実際に読めるか**だけを確かめます。

1. `PROFILE.md` の「参照する主なフォルダ」から、1つ選ぶ。
   **「AI に読ませない場所」に挙がっている場所は選ばないこと**
   - `PROFILE.md` が無い・白紙運用・場所が書かれていない →
     「**資料の場所が登録されていないため、試していません**」と報告して 7 へ進む（異常ではない）
2. そのフォルダに Glob などの内蔵検索をかけ、**ファイル名を列挙できるか**だけを確かめる。
   **ファイルの中身は開かないこと**

| 起きたこと | 判定と案内 |
|---|---|
| 列挙できた | 正常。**どのフォルダで試したか**を書く |
| 「この先も読み続けてよいか」の確認が出た | 「**Keep allowing** を選んでください。**Block from now on** は選ばないでください」と案内する |
| フォルダが見つからない | ネットワークドライブが繋がっていない可能性がある。エクスプローラーで開けるか、ユーザーに確かめてもらう |
| 読み取りを拒否された | 以前「Block from now on」を選んだ可能性がある（下記） |

「Block from now on」を選ぶと、ユーザー設定（`%USERPROFILE%\.claude\settings.json`）の
`permissions.blockReadsOutsideWorkingDirectories` が `true` になり、**すべての作業で AI-DESK の外を読めなくなります。**
**あなたがこの設定を直してはいけません**（AI-DESK の外への書き込みです）。
ユーザーに、その行を消してから Claude Code を起動し直すよう案内してください。

## 7. Python が使えるか

**`python` ではなく `py` を使い、ライブラリまで確かめる。**

```powershell
py -c "import sys, openpyxl, pandas, docx, pptx, pdfplumber; print(sys.executable)"
```

- **実体のパスが返った → 正常。** そのパスを報告する
- **エラー → 使えない。** 次のどちらかを切り分ける
  - `py` が無い、または Python 本体が無い → **導入の可否をユーザーに確認したうえで**
    `powershell -NoProfile -ExecutionPolicy Bypass -File "<インスタンスのルート>\bin\setup_python.ps1"`
    を実行し、**終了後に Claude Code の再起動を案内する**
  - Python はあるがライブラリが足りない → **確認不要。** `py -m pip install` で入れる

### 7-2. `python` が何を指しているか（警告のための確認）

```powershell
where python
```

返ってきたパスを見て、**次のどちらかなら警告してください。**

| 見つかったもの | 何が問題か |
|---|---|
| パスに `WindowsApps` を含む | Microsoft Store の誘導用スタブ（偽物）。実行しても動かない |
| **別アプリに同梱された Python**（`Inkscape`、`GIMP`、`Blender` などのフォルダの下） | 抽出ライブラリが入っておらず、**そこへ `pip install` すると他アプリの環境を壊す** |

どちらかだった場合は、
**「`python` は別物を指しています。`py` を使ってください」とユーザーに伝えてください。**
`python` が正規の Python を指していた場合も、**`py` を使う方針は変わりません**
（PC ごとに違うためです）。

**7 と 7-2 は別の確認です。** 7 が正常でも 7-2 の警告は出しうるので、両方報告してください。

## 8. 書き込みの制限が効いているか

**ここは「書ける」ことと「書けない」ことの両方を確かめる項目です。**

この AI-DESK は既定で Auto モードで動くため、**確認プロンプトは歯止めになりません。**
書き込み先を限っているのは、`.claude\settings.json` に登録された **hook**（`.claude\hooks\guard-write.ps1`）です。
hook は、AI がファイルを書く直前に書き込み先**と名前**を調べ、次以外への書き込みを、**モードに関係なく**止めます。

- `<タスクフォルダ>\` の中の、`00_` で始まるファイル・`NNA_` / `NNB_` で始まるファイル・
  `NNB_` で始まるフォルダの中・`材料\` の中（**ただし `00_TASK.md` は除く**）。
  保管フォルダ（`_保管…\`）の直下にあるタスクフォルダも、同じ扱いです
- `PROFILE.md`
- `.claude\skills\` の中

### 8-1. 仕組みが揃っているか（読むだけ）

| 確かめること | 揃っていないとき |
|---|---|
| `.claude\hooks\guard-write.ps1` がある | **異常。** 管理者に更新を依頼するよう案内する |
| `.claude\settings.json` の `hooks` → `PreToolUse` に、`guard-write.ps1` を呼ぶ設定がある | **異常。** 同上 |
| `.claude\settings.json` と `.claude\settings.local.json` のどちらにも、`"disableAllHooks": true` が無い | **異常。** hook が止められています。どのファイルに書かれているかを示す |

以前の版で作られた `.claude\settings.local.json` が残っていることがあります。
**`disableAllHooks` が書かれていなければ、残っていても害はありません。**

**異常を見つけても、あなたが設定ファイルを直してはいけません**（書こうとしても止まります）。
何が足りないかを示して、ユーザーに伝えてください。

### 8-2. タスクフォルダに書けるか

点検用のタスクフォルダ `00_疎通確認` を使い、**`00_疎通確認\00_点検記録.md`** に書いてください。

- フォルダが無くても構いません。**書き込めば作られます**
- **業務のタスクフォルダと区別するため、名前の頭は `00_` です。** 変えないでください
- **毎回このファイルを上書きします。** 番号を増やさないでください。点検の記録は1つで足ります
- ここではまず日付だけを書き、**点検がすべて終わったら、結果の要約で上書き**してください
- 書けた → 正常
- **書けなかった → 異常。** 止められたときの文を、そのまま報告してください。
  これが起きると、この AI-DESK は何も出力できません。疑うことは次のとおりです
  - `.claude\settings.json` の `deny` の書き方（先頭が `/` でないと、deny では深さを問わず当たります）
  - 「AI-DESK の書き込み制限で…」と止められた場合は、`.ai-desk\VERSION` がカレントディレクトリにあるか
    （hook は、スクリプトの2つ上のフォルダをインスタンスのルートとして判定します）

### 8-3. 配布物への書き込みが拒否されるか

試す前に、**必ず次のようにユーザーに伝えてください。**

> これから、わざと間違った場所へ書き込もうとします（8-3 と 8-4 の2回です）。
> **止められるのが正しい動作です。** 万一、確認が出た場合は「いいえ」と答えてください。

**`00_タスクテンプレート\点検.txt`** を作ろうとしてください。
ここは `deny`（`Edit(/00_タスクテンプレート/**)`）に挙げてあります。

| 起きたこと | 判定 |
|---|---|
| **止められた**（確認も出ない） | **正常** |
| 確認プロンプトが出た（ユーザーには断ってもらう） | **異常。** hook も `deny` も効いていません |
| **書けてしまった** | **異常。** すぐに報告すること |

### 8-4. 【重要】hook が働いているか

**これは、この点検で最も大事な検査です。**

**`00_疎通確認\メモ.md`** を作ろうとしてください
（点検用タスクフォルダの中ですが、**書いてよい名前ではありません**）。
この場所は `deny` に挙げていないため、**止まるとすれば hook の働きです。**

| 起きたこと | 判定 |
|---|---|
| **「AI-DESK の書き込み制限で、この書き込みを止めました」**と止められた | **正常。** hook が働いています |
| 確認プロンプトが出た（ユーザーには断ってもらう） | **異常。** hook が働いていません |
| **書けてしまった** | **異常。** hook が働いていません。すぐに報告すること |

**hook が働いていないと、AI-DESK の外（資料フォルダを含む）への書き込みも、
人が書いた `00_TASK.md` の上書きも止まりません。**
異常だった場合は、他がすべて正常でも、**作業を始める前に直すよう**はっきり伝えてください。
疑うことを、順に挙げてください。

1. 「このフォルダを信頼しますか」に承諾しているか（**信頼していないと hook は動きません**）
2. 8-1 の3項目
3. Claude Code を最新版に更新して、試し直す（`claude --version` で版が分かります）
4. PowerShell のスクリプト実行が、会社の設定（グループポリシー）で禁止されていないか

**8-3・8-4 で書けてしまった場合、そのファイルを自分で消さないでください**（絶対遵守ルール4）。
どこに何を作ってしまったかを正確に報告し、ユーザーに削除を依頼してください。

## 9. インスタンスの構成

カレントディレクトリ直下に次があるか確認する。無いものは指摘する。

- `CLAUDE.md`
- `GEMINI.md`
- `.claude\settings.json`（`permissions.deny` に `Edit(*/00_TASK.md)` があるか）
- `.claude\hooks\guard-write.ps1`
- `00_タスクテンプレート\`（中に `00_TASK.md` と `README.md` があるか）
- `bin\`

以前の版の `task_template\` や、タスクフォルダの中の `out\` が残っていても、異常ではありません。
「1.1.0 までの置き場です。中身を確かめて、手で片付けて構いません」と伝えてください
（**あなたは消さないこと**）。

名前が `_保管` で始まるフォルダ（`_保管庫` など）は**保管フォルダ**です（→ `CLAUDE.md`「保管フォルダ」）。
配布物には `_保管庫\` が入っていますが、**無くても、名前が変えてあっても、いくつあっても異常ではありません。**
保管フォルダがあれば、その名前を報告してください。

不足していれば、**管理者に更新を依頼するよう案内する**（AI が勝手にコピーしない）。

あわせて、**インスタンスの中に `.git` が無いこと**を確認する。
**あった場合は異常**として報告すること。インスタンスは Git のクローンではありません
（→ `CLAUDE.md` 絶対遵守ルール2）。

## 10. 履歴の一覧が出るか（ネットワークドライブのとき）

この AI-DESK は、セッションを始めるたびに、履歴の一覧の問題を自動で直します。ここでは、それが済んでいるかを確かめます。

次を実行する。**調べるだけなので、承諾は要りません。**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<インスタンスのルート>\bin\setup_history.ps1" -CheckOnly
```

| 出力 | 判定と案内 |
|---|---|
| 「ネットワークドライブではありません」「この問題は起きません」 | 正常 |
| 「対処済みです」 | 正常 |
| 「まだ対処されていません」 | **自動の修正が働いていません。** セッション開始時の hook が動いていない可能性がある（8-4 と同じく、信頼の承諾と `disableAllHooks` を疑う）。そのうえで `CLAUDE.md` の「実行環境について（Windows）」11 のとおり、**承諾を得てから** `-CheckOnly` を付けずに実行する |
| それ以外（対処できない、別のリンクがある など） | 出力をそのまま報告する。**自分でジャンクションを作ったり、フォルダを動かしたりしない** |

## 報告のしかた

1〜10（1-2 を含む）を表にまとめ、**問題があった項目だけ**、次に何をすればよいかを添えて報告します。
報告の内容は、8-2 の点検記録にも要約して書きます。

**問題が無くても必ず示すもの:**

- **インスタンスのフルパスと版番号**（1）
- **配布元との版の比較結果**（2）。確認できなかった場合は、その理由

それ以外がすべて正常なら「問題なし」と一行で締めてよい。

**「確認できませんでした」と「異常です」を混ぜないでください。**
届かなかっただけのものを異常として報告しない。逆に、
**1-2 で Windows 以外だったとき、8-3 または 8-4 が素通りしたときは、他がすべて正常でも「異常」と明記してください。**
