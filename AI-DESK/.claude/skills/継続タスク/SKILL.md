# 継続タスク — 2回目以降の作業

同じタスクフォルダで作業を続けるときの手順です。
**依頼を最初からやり直さないこと。** 前回の続きから始めます。

## 0. 出力先を確定し、宣言する（最初にやること）

作業を始める前に、**今回のタスクフォルダ名を確定**してください。
ユーザーが「202610_見積比較 の続き」と言ったなら、タスクフォルダは `202610_見積比較` です。

そのうえで、**次の1行をユーザーに示してから**作業に入ります。

    出力先: <インスタンスのルート>\<タスク名>\

**このパスにタスクフォルダ名が入っていなければ間違いです。**
インスタンスのルート直下に、直接ファイルを置くことはできません。

> 「**out2 に作って**」のように言われることがあります。
> **`out`・`out2` は 1.2.0 で廃止しました。** 成果物はタスクフォルダの直下に出し、
> 回ごとに番号が変わることを伝えてください（`02B_…` のように別のファイルになります）。

読み込むフォルダ（資料の置き場所）と、書き込むフォルダは**常に別**です。
依頼や作業記録に出てくるパスは、断りがない限り**すべて「読む場所」**です。

## 1. 作業記録を読む

`<タスクフォルダ>\00_作業記録.md` を読みます。どの回の記録も、ここにまとまっています。

- **ある場合** → 一番下の「次にできること」と、その後の「返事」を確認する。ここが再開地点です。
  あわせて `## 毎回守ること` に**育てるファイル**の行（「〜は `00_…` を直していく」）があるか見ます。
  **あれば、4. の「育てるファイルのとき」の手順で出します。無ければ、ふだんどおり `NNB_…` です。**
- **無い場合** → 今回が実質2回目です。`<タスクフォルダ>\` の既存ファイルと依頼から
  経緯を復元し、**今回の作業のあとで `00_作業記録.md` を新規に作ります。**
  （過去分は分かる範囲で埋め、埋められないところは「記録なし」と書く。推測で埋めない）

次に**依頼を読み、目的を確認します。** 依頼は「変わらない目的」、作業記録は「そこまでの経緯」です。
両方が必要です。

| 探す順 | ファイル |
|---|---|
| 1 | `00_TASK.md`（込み入った依頼のときだけ置かれます。**無いのがふつうです**） |
| 2 | `<タスクフォルダ>\01A_依頼内容.md` —— **`00_TASK.md` が無いときは、これが依頼です** |

チャットで始められたタスクには、`00_TASK.md` がありません。
**そのときは `01A_依頼内容.md` が「変わらない目的」の記録です**（→ `新規タスク` スキル）。

## 2. 何をするか決める

ユーザーの言い方によって決まります。

| 言われ方 | すること |
|---|---|
| 「1番で」「2番、ただし〜」 | 前回の「次にできること」の該当項目を実行する |
| 「続き」「続きをやって」 | 「次にできること」の1番を実行する。ただし**着手前に「1番の〜を進めます。よろしいですか」と一言確認する** |
| 具体的な指示 | その指示に従う |

`## 毎回守ること` の項目は、**言われなくても全部守ります。**

## 3. 今回の依頼を書き留める — `NNA_依頼内容.md`

**作業を始める前に書きます。** 読み取りを誤ったまま長時間作業してしまうのを、ここで防ぎます。

`NN` は**今回の回次**です。前回が第1回なら `02A_依頼内容.md` になります。
**置き場所は、タスクフォルダの直下**です。

```markdown
# 第2回の依頼

- 出どころ: チャット（2026-10-18）
- 前回までの依頼: `01A_依頼内容.md`（`00_TASK.md` があるタスクでは `00_TASK.md`）

## 頼まれたこと

（前回の「次にできること」の1番。4社目の見積を加えて、表を作り直す）

## 見る場所

（今回あらたに見る場所があれば書く。無ければ「前回と同じ」）

## 成果物の形

## 注意してほしいこと

## 原文

> （言われた言葉を、そのまま貼る）
```

**「原文」がこのファイルの中心です。**
あなたの読み取りは誤ることがありますが、原文は誤りません。
チャットの履歴は消えることがあります。**ここに残したものだけが残ります。**
**要約したり、言い回しを整えたりしないでください。**

同じ回の途中で依頼が変わったとき（「やっぱり docx で」など）は、**このファイルを更新します。**
番号を増やすのは、回が変わったときだけです。

## 4. 作業して、成果物を出す

出力先は **0. で宣言したパス**です。ファイル名は次の形式にします。

```
NNB_内容を表す日本語名_YYYY-MM-DD.拡張子
        例: 02B_見積比較_4社版_2026-10-18.md
```

`NN` は回次（01, 02, 03 …）、**`A` が依頼、`B` がその結果**です。
**時系列と、依頼・結果の対応が一目でわかり、上書き事故も防げます。**
**日付を後ろに置くのは、名前の方が大事だからです**（幅が足りないとき、切れるのは末尾です）。

- **`NN` は、3. で書いた `NNA_依頼内容.md` と必ず同じ番号にします。**
  `02A_依頼内容.md` を書いた回の成果物は、**必ず `02B_…`** です。
  **前の回のファイル名で出さないでください。前の回の成果物が消えます。**
- 「**短くして**」「**書き直して**」「**作り直して**」と言われた回も同じです。
  **作り直しの依頼は、前のものを消してよいという意味ではありません。**
  新旧を見比べて、どちらを使うかを決めるのはユーザーです。
- **同じファイルを更新してよいのは、同じ回の中だけです**
  （3. を書いてから、その回の成果物を仕上げるまでの間）。**回が変われば、番号も変わります。**
  例外は、ユーザーの承諾を得た**育てるファイル**だけです（→ 下の「育てるファイルのとき」）
- 1回で3つ以上のファイルを出すときは、
  `<タスクフォルダ>\NNB_タイトル_YYYY-MM-DD\` というサブフォルダにまとめます。
  **`NNA_依頼内容.md` は直下に残し、この「3つ」にも数えません。**
- 抽出スクリプト・中間データ・バックアップは `<タスクフォルダ>\材料\` に入れ、
  直下には置きません。**直下は「ユーザーが読むもの」だけにします。**
- **これ以外の名前のフォルダを、タスクフォルダの中に作らないでください。**
  書き込みの制限で止まります。

> **実際に起きた事故です。** 第1回で長すぎる議事録を作り、第2回で「3ページに短くして」と
> 頼まれました。短くしたものを**第1回と同じファイル名**で出したため、
> **第1回の議事録は消え、元に戻せませんでした。**
> 第2回の成果物は `02B_議事録_YYYY-MM-DD.md` です。

1.1.0 までは、タスクフォルダの中の `out\` に `NN_名前_YYYY-MM-DD.拡張子`（`A` / `B` の別なし）で
出していました。**その形のファイルやフォルダが残っていても、改名も移動もしないでください**
（絶対遵守ルール4）。置き場所を変えるのは、管理者の仕事です。

**Python スクリプトを書くときは、書き出し先のパスを必ず目視確認してください。**
`open(path, "w")` や `to_excel(path)` の path に、タスクフォルダ名が入っていますか。

### 育てるファイルのとき（`## 毎回守ること` にその行があるタスクだけ）

1つの成果物を、`00_[日本語名].拡張子`（例: `00_議事録.md`）のまま回をまたいで直していきます
（→ `CLAUDE.md`「出力と保存のルール」2 の「育てるファイル」）。**手順は次の順です。**

1. 3. の `NNA_依頼内容.md` は、**ふだんどおり書きます**
2. **書き換える前に**、前の回の控え（`材料\` の中の、前の回の番号の `NNB_…`）があることを確かめます。
   **無ければ、書き換える前に `Copy-Item` で写します**（名前は前の回の番号と日付。日付は作業記録から）
3. `00_[日本語名]` を直します。同じ回の中なら、何度直しても構いません
4. **回の終わりに、仕上がったものを `材料\NNB_[日本語名]_YYYY-MM-DD.拡張子` に `Copy-Item` で写します。**
   `NN` は 3. の `NNA_依頼内容.md` と同じ番号です（`03A` を書いた回なら `材料\03B_…`）

```
例: 第3回
    02B の控えがあることを確かめる   材料\02B_議事録_2026-10-16.md
    直す                            00_議事録.md
    写す                            材料\03B_議事録_2026-10-17.md
```

**写し先のパスにタスクフォルダ名が入っていることを確かめてください。**
`Copy-Item` はシェルのコマンドなので、書き込みの制限では止まりません。

「短くして」「書き直して」と言われた回も、この手順のままです。**控えがあるので、前の版は消えません。**

### 育てるファイルに切り替えるとき

**ユーザーの承諾があったときだけ**切り替えます。自分の判断で切り替えないでください
（提案のしかたは 6.）。

- いちばん新しい `NNB_…` を、`00_[日本語名].拡張子` に **`Copy-Item` で写して**から直します
- **それまでの `NNB_…` は、改名も移動もしません**（絶対遵守ルール4）。直下に残ったままで構いません
- 前の回の版は直下の `NNB_…` として残っているので、**この回だけは、前の回の控えを `材料\` に写しません**
  （上の「育てるファイルのとき」の 2. は飛ばします）
- 名前に日付は付けません。`00_TASK.md`・`00_作業記録.md` とは別の名前にします。対象はファイル1つだけです
- 5. の `## 毎回守ること` に、次の1行を足します。**次の回は、この行を見て判断します**

      - 議事録は `00_議事録.md` を直していく（第3回から。各回の控えは `材料\`）

- その回の終わりの控え（上の 4.）も、ふだんどおり取ります

## 5. 作業記録に追記する

`<タスクフォルダ>\00_作業記録.md` に、次の2つを書きます。
**これを忘れると次回の続きができません。**

### (a) 今回の回を追記する

`## 経緯` の末尾に足します。その見出しが無い古い記録では、ファイルの末尾に足して構いません。

```markdown
### 第N回 YYYY-MM-DD
- 依頼: （1行の要約。詳細は `NNA_依頼内容.md`）
- 見た資料: （パス。おおよそでよい）
- わかったこと:
- できなかった・見つからなかったこと: （無ければ「なし」）
- 成果物: NNB_名前_YYYY-MM-DD.md
- 次にできること:
  1.
  2.
  3.
```

育てるファイルのタスクでは、「成果物」の欄を次のように書きます。

    - 成果物: 00_議事録.md を更新（控え: 材料\03B_議事録_2026-10-17.md）

**「依頼」の欄に、言われた言葉を書き写さないでください。**
それは `NNA_依頼内容.md`（→ 3.）の仕事です。両方に書くと二重管理になり、必ず食い違います。
ここは1行の要約と、参照だけにします。

### (b) 冒頭を書き換える

- `## いまの状況` — 「第N回まで完了。最新の成果物は …。次の指示待ち」の形で**上書き**する
- `## 毎回守ること` — 今回ユーザーから出た指摘のうち、**次回以降も有効なもの**を1行足す
  （例:「金額は税込で書く（第2回の指摘）」）。その場限りの指示は足さない

**ユーザーがチャットで言った指示も、`### 第N回への返事` として書き写します。**
ユーザーにファイルを編集させないこと。

## 6. 「次にできること」を必ず出す

**これがこのスキルの中心です。** 毎回、成果物の末尾と作業記録の両方に、
**2〜3個**を番号付きで書きます。

良い提案の条件:

- **具体的な動作**であること（「検討する」ではなく「A社に出す質問状の案を作る」）
- **今回わかったことから自然に続く**こと
- **やらない選択肢も混ぜてよい**（「このまま会議に出す（追加作業なし）」も立派な選択肢）
- 4個以上は出さない。選べなくなります

**同じ成果物を2回続けて直した回**（例: 第2回も第3回も議事録を直した）で、まだ育てるファイルにしていなければ、
次の1つを提案に混ぜて構いません。**承諾されるまでは、ふだんどおり `NNB_…` で出します。**

> 次の回から、`00_議事録.md` の1つを直していく形にする（これまでの版は `材料\` に控えとして残ります）

提案が思いつかない場合は、**無理に絞り出さず「次にできることは思いつきません。
ここで完了にしてよいと考えます」と正直に書きます。**

## 7. 報告のしかた

チャットには次を短く伝えます。

1. 今回やったこと（1〜2行）
2. **成果物のフルパス**（`<インスタンスのルート>\<タスク名>\…`）。
   タスクフォルダ名まで書く。ユーザーが場所の間違いに即座に気づけるようにするためです
3. **次にできること（番号付き）** ← 番号で答えられる形にする
4. 処理できなかったファイルや、見つからなかった項目があればその旨

## 注意

- **同じ目的なら、同じタスクフォルダで回を重ねます。** 新しいフォルダを作らないこと。
  目的そのものが変わったときだけ、新しいタスクフォルダを提案します。
- 作業記録が長くなっても**古い回を消さないこと。** 経緯が価値です。
- **間違った場所にファイルを作ってしまったら、自分で消したり移動したりしないこと。**
  どこに何を作ってしまったかを正確に報告し、指示を仰いでください（絶対遵守ルール4）。
- 同じ指摘が**別のタスクでも**繰り返し出るようになったら、
  「これは `PROFILE.md` に書きませんか」「スキルにしませんか」とユーザーに提案します。
  - `PROFILE.md` と、このインスタンスのスキルは、**承諾を得れば直せます**
  - ただし**配布物のスキル**（`疎通確認`・`新規タスク`・`継続タスク`）を直接書き換えると、
    次の更新で消えます。別の名前でコピーを作るか、改訂案を
    `<タスクフォルダ>\` に出して管理者に渡してください
  - `CLAUDE.md` は配布物です。**その場では直さず**、改訂案を出します
