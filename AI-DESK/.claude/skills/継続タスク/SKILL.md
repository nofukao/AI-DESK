# 継続タスク — 2回目以降の作業

同じタスクフォルダで作業を続けるときの手順です。
**TASK.md を最初からやり直さないこと。** 前回の続きから始めます。

## 0. 出力先を確定し、宣言する（最初にやること）

作業を始める前に、**今回のタスクフォルダ名を確定**してください。
ユーザーが「202610_見積比較 の続き」と言ったなら、タスクフォルダは `202610_見積比較` です。

そのうえで、**次の1行をユーザーに示してから**作業に入ります。

    出力先: <インスタンスのルート>\<タスク名>\out\

ユーザーが「out2 に作って」のように、`out` に数字を付けた名前を指定したときは、最後の `out\` が `out2\` になります。
指定が無ければ `out\` です（前の会話で `out2` を使っていても、この会話で指定が無ければ `out\` です）。

**このパスにタスクフォルダ名が入っていなければ間違いです。**
インスタンスのルート直下の `out`（`out2` なども）は、いかなる場合も使いません。

読み込むフォルダ（資料の置き場所）と、書き込むフォルダは**常に別**です。
TASK.md や作業記録に出てくるパスは、断りがない限り**すべて「読む場所」**です。

## 1. 作業記録を読む

`<タスクフォルダ>\out\00_作業記録.md` を読みます。`out2` などに出した回の記録も、ここにまとまっています。

- **ある場合** → 一番下の「次にできること」と、その後の「返事」を確認する。ここが再開地点です。
- **無い場合** → 今回が実質2回目です。`<タスクフォルダ>\out\` の既存ファイル（`out2\` などがあれば、その中も）と `TASK.md` から
  経緯を復元し、**今回の作業のあとで `00_作業記録.md` を新規に作ります。**
  （過去分は分かる範囲で埋め、埋められないところは「記録なし」と書く。推測で埋めない）

次に**依頼を読み、目的を確認します。** 依頼は「変わらない目的」、作業記録は「そこまでの経緯」です。
両方が必要です。

| 探す順 | ファイル |
|---|---|
| 1 | `TASK.md`（無ければ `task.txt`。大文字・小文字は問わない） |
| 2 | `<タスクフォルダ>\out\01_依頼内容.md` —— **`TASK.md` が無いときは、これが依頼です** |

`TASK.md` を置かずにチャットで始められたタスクには、`TASK.md` がありません。
**そのときは `01_依頼内容.md` が「変わらない目的」の記録です**（→ `新規タスク` スキル）。

**以前の版で作られたタスクには `NN_依頼内容.md` がありません。異常ではありません。**
`TASK.md` と作業記録から、これまでどおり続けてください。

## 2. 何をするか決める

ユーザーの言い方によって決まります。

| 言われ方 | すること |
|---|---|
| 「1番で」「2番、ただし〜」 | 前回の「次にできること」の該当項目を実行する |
| 「続き」「続きをやって」 | 「次にできること」の1番を実行する。ただし**着手前に「1番の〜を進めます。よろしいですか」と一言確認する** |
| 具体的な指示 | その指示に従う |

`## 毎回守ること` の項目は、**言われなくても全部守ります。**

## 3. 今回の依頼を書き留める — `NN_依頼内容.md`

**作業を始める前に書きます。** 読み取りを誤ったまま長時間作業してしまうのを、ここで防ぎます。

`NN` は**今回の回次**です。前回が第1回なら `02_依頼内容.md` になります。
**置き場所は、今回の成果物と同じフォルダ**です（`out2` に出す回なら `out2\02_依頼内容.md`）。
`out2\` だけを開いた人が、`out\` を遡らなくても何を頼まれたのか分かるようにするためです。

```markdown
# 第2回の依頼

- 出どころ: チャット（2026-10-18）
- 前回までの依頼: `TASK.md`（`TASK.md` が無いタスクでは `01_依頼内容.md`）

## 頼まれたこと

（前回の「次にできること」の1番。4社目の見積を加えて、表を作り直す）

## 見る場所

（今回あらたに見る場所があれば書く。無ければ「前回と同じ」）

## 成果物の形

## 注意してほしいこと

## 原文

> （言われた言葉を、そのまま貼る）
```

**「原文」がこのファイルの中心です。**
あなたの読み取りは誤ることがありますが、原文は誤りません。
チャットの履歴は消えることがあります。**ここに残したものだけが残ります。**
**要約したり、言い回しを整えたりしないでください。**

同じ回の途中で依頼が変わったとき（「やっぱり docx で」など）は、**このファイルを更新します。**
番号を増やすのは、回が変わったときだけです。

## 4. 作業して、成果物を出す

出力先は **0. で宣言したパス**です。ファイル名は次の形式にします。

```
NN_内容を表す日本語名_YYYY-MM-DD.拡張子
        例: 02_見積比較_4社版_2026-10-18.md
```

`NN` は回次（01, 02, 03 …）です。**時系列が一目でわかり、上書き事故も防げます。**
`out2` などに出す回も、番号は `out` と通しで数えます（3回目なら `out2\03_…`）。
**日付を後ろに置くのは、名前の方が大事だからです**（幅が足りないとき、切れるのは末尾です）。

以前の版では `NN_YYYY-MM-DD_名前.拡張子`（日付が前）でした。
**その形のファイルが残っていても、改名しないでください**（絶対遵守ルール4）。
`NN` が先頭なのは変わらないので、新旧が混ざっても回次の並び順は崩れません。

- **確定した成果物は、後の回で上書きしません。** 新しい番号で出します。
- **推敲中のドラフト**（ユーザーが「ここを直して」と繰り返し磨いているもの）は、
  **同じファイルを更新して構いません。** 複製すると `out` が散らかるためです。
  どちらか迷ったら「同じファイルを直しますか、新しい番号で出しますか」と一言聞いてください。
- 1回で3つ以上のファイルを出すときは、
  `<タスクフォルダ>\out\NN_タイトル_YYYY-MM-DD\` というサブフォルダにまとめます。
  **`NN_依頼内容.md` は `out` 直下に残し、この「3つ」にも数えません。**
- 抽出スクリプト・中間データ・バックアップは `<タスクフォルダ>\out\材料\` に入れ、
  `out` 直下には置きません。**`out` 直下は「ユーザーが読むもの」だけにします。**

**Python スクリプトを書くときは、書き出し先のパスを必ず目視確認してください。**
`open(path, "w")` や `to_excel(path)` の path に、タスクフォルダ名が入っていますか。

## 5. 作業記録に追記する

`<タスクフォルダ>\out\00_作業記録.md` に、次の2つを書きます（成果物を `out2` などに出した回も、書くのはこのファイルです）。
**これを忘れると次回の続きができません。**

### (a) 今回の回を追記する

`## 経緯` の末尾に足します。その見出しが無い古い記録では、ファイルの末尾に足して構いません。

```markdown
### 第N回 YYYY-MM-DD
- 依頼: （1行の要約。詳細は `NN_依頼内容.md`）
- 見た資料: （パス。おおよそでよい）
- わかったこと: 
- できなかった・見つからなかったこと: （無ければ「なし」）
- 成果物: NN_名前_YYYY-MM-DD.md（`out` 以外に出したときは `out2\NN_…` のようにフォルダ名から書く）
- 次にできること:
  1. 
  2. 
  3. 
```

**「依頼」の欄に、言われた言葉を書き写さないでください。**
それは `NN_依頼内容.md`（→ 3.）の仕事です。両方に書くと二重管理になり、必ず食い違います。
ここは1行の要約と、参照だけにします。

### (b) 冒頭を書き換える

- `## いまの状況` — 「第N回まで完了。最新の成果物は …。次の指示待ち」の形で**上書き**する
- `## 毎回守ること` — 今回ユーザーから出た指摘のうち、**次回以降も有効なもの**を1行足す
  （例:「金額は税込で書く（第2回の指摘）」）。その場限りの指示は足さない

**ユーザーがチャットで言った指示も、`### 第N回への返事` として書き写します。**
ユーザーにファイルを編集させないこと。

## 6. 「次にできること」を必ず出す

**これがこのスキルの中心です。** 毎回、成果物の末尾と作業記録の両方に、
**2〜3個**を番号付きで書きます。

良い提案の条件:

- **具体的な動作**であること（「検討する」ではなく「A社に出す質問状の案を作る」）
- **今回わかったことから自然に続く**こと
- **やらない選択肢も混ぜてよい**（「このまま会議に出す（追加作業なし）」も立派な選択肢）
- 4個以上は出さない。選べなくなります

提案が思いつかない場合は、**無理に絞り出さず「次にできることは思いつきません。
ここで完了にしてよいと考えます」と正直に書きます。**

## 7. 報告のしかた

チャットには次を短く伝えます。

1. 今回やったこと（1〜2行）
2. **成果物のフルパス**（`<インスタンスのルート>\<タスク名>\out\…`。`out2` に出したときは `…\out2\…`）。
   `out\` とだけ書かない。ユーザーが場所の間違いに即座に気づけるようにするためです
3. **次にできること（番号付き）** ← 番号で答えられる形にする
4. 処理できなかったファイルや、見つからなかった項目があればその旨

## 注意

- **同じ目的なら、同じタスクフォルダで回を重ねます。** 新しいフォルダを作らないこと。
  目的そのものが変わったときだけ、新しいタスクフォルダを提案します。
- 作業記録が長くなっても**古い回を消さないこと。** 経緯が価値です。
- **間違った場所にファイルを作ってしまったら、自分で消したり移動したりしないこと。**
  どこに何を作ってしまったかを正確に報告し、指示を仰いでください（絶対遵守ルール4）。
- 同じ指摘が**別のタスクでも**繰り返し出るようになったら、
  「これは `PROFILE.md` に書きませんか」「スキルにしませんか」とユーザーに提案します。
  - `PROFILE.md` と、このインスタンスのスキルは、**承諾を得れば直せます**
  - ただし**配布物のスキル**（`疎通確認`・`新規タスク`・`継続タスク`）を直接書き換えると、
    次の更新で消えます。別の名前でコピーを作るか、改訂案を
    `<タスクフォルダ>\out\` に出して管理者に渡してください
  - `CLAUDE.md` は配布物です。**その場では直さず**、改訂案を出します
