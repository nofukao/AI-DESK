# 新規タスク — チャットで直接頼まれたとき

チャットでそのまま依頼されたときの手順です。**AI-DESK でいちばんよくある頼まれ方です。**

**あなたが `00_TASK.md` を書くのではありません。**
`00_TASK.md` は、人が書く依頼の**原本**で、込み入った依頼のときだけ前もって置かれます。
あなたは聞き取った依頼を `<タスクフォルダ>\01A_依頼内容.md` に書き起こします（→ 3.）。
**この2つを混ぜないこと**が、このスキルでいちばん大事な点です。
混ぜると、あとから「この条件は人が決めたのか、AI が補ったのか」が分からなくなります。

## 0. そもそもタスクフォルダを作る場面か

**作るのは、ファイル（成果物）を作る依頼のときだけです。**

| 言われたこと | どうするか |
|---|---|
| 「〜の一覧を xlsx で作って」「〜をまとめて」 | **タスクフォルダを作る。** このスキルの手順へ |
| 「〜ってどこにある?」「この数字は何?」 | **作らない。** チャットで答えて終わり |
| 「〜の続き」「〜を直して」 | **作らない。** `継続タスク` スキルへ |
| 既にあるタスクフォルダの名前が出た | **作らない。** `継続タスク` スキルへ |

**迷ったら作らないでください。** 質問のたびにフォルダが増えると、
インスタンスのルートが散らかり、どれが本当の依頼か分からなくなります。
「これはタスクにしますか」と一言聞けば済みます。

## 1. タスクフォルダの名前を決める

依頼の内容が分かる**短い日本語**にします（例: `差出人名簿`、`見積比較`）。
**フォルダ名が、そのままこの依頼の呼び名になります。**
次回「差出人名簿の続き」と呼べる名前にしてください。

**次の名前は使えません。** これらを付けると、書き込みの制限が
「タスクフォルダではない」と判定し、**その中に1つもファイルを置けなくなります。**

- `bin` / `out`・`out2`・`out3` …（`out` に数字を付けたもの）
- `00_タスクテンプレート`
- `.` で始まる名前
- `_保管` で始まる名前（保管フォルダの印です → `CLAUDE.md`「保管フォルダ」）

**作る場所は、必ずルート直下です。** 保管フォルダ（`_保管…\`）の中には作りません。

Windows の制限も守ります。

- 使えない文字: `\ / : * ? " < > |`
- 末尾に空白やドットを置かない
- `CON` `PRN` `AUX` `NUL` `COM1` … `LPT1` … は単独で使わない
- 長くしすぎない（パス全体で260文字の制限があります
  → `CLAUDE.md`「実行環境について（Windows）」10）

日付の接頭辞は**付けません**。呼びやすさを優先します。

**同じ名前のフォルダが既にあったら、黙って使わないでください。**
「前回の続きですか、それとも別件ですか」と聞きます。
別件なら、区別できる名前を一緒に決めます（`差出人名簿_2026年度` など）。

**保管フォルダの中も見ます。** ルート直下に無くても、`_保管庫_仕事\差出人名簿\` のように
保管フォルダの直下に同じ名前があれば、同じように聞きます。
続きなら、**そのフォルダの場所のまま** `継続タスク` スキルで続けます（ルート直下に新しく作りません）。

> 共有フォルダに置かれた AI-DESK では、**このフォルダ名が他の人からも見えます。**
> 取引先名や個人名をそのまま名前にしてよいか、迷ったら聞いてください。

## 2. 出力先を宣言する

ファイルを1つでも作る前に、**次の1行を示します。**

    出力先: <インスタンスのルート>\<タスク名>\

**承諾を待つ必要はありません。** 示したら、そのまま次へ進みます。
名前が気に入らなければ、ユーザーがあとでフォルダを改名できます
（**あなたは改名しないでください** → 絶対遵守ルール4）。

**このパスにタスクフォルダ名が入っていなければ、その時点で間違っています。**

## 3. 依頼を書き起こす — `01A_依頼内容.md`

**作業を始める前に書きます。** 読み取りを誤ったまま長時間作業してしまうのを、ここで防ぎます。

`<タスクフォルダ>\01A_依頼内容.md` に、次の形で書きます。
フォルダはまだ無くて構いません。**書き込めば作られます。`mkdir` を別に実行しないでください。**

```markdown
# 第1回の依頼

- 出どころ: チャット（2026-09-16）
- **この文書が依頼の記録です**（`00_TASK.md` はありません）

## 頼まれたこと


## 見る場所


## 成果物の形


## 注意してほしいこと


## 完成の条件


## 原文

> （言われた言葉を、そのまま貼る）
```

**「原文」がこのファイルの中心です。**
あなたの読み取りは誤ることがありますが、原文は誤りません。
チャットの履歴は消えることがあります。**ここに残したものだけが残ります。**
**要約したり、言い回しを整えたりしないでください。**

書けない項目は空欄で構いません。ただし**「見る場所」だけは別です。**

- 資料の場所が読み取れないときは、**ここで聞いてください。** 作業を始めてからでは遅すぎます
- 「`Z:` の設備関係のどこか」程度の手がかりでも、当てずっぽうに探すよりはるかに速くなります

同じ回の途中で依頼が変わったとき（「やっぱり docx で」など）は、**このファイルを更新します。**
番号を増やすのは、回が変わったときだけです。

> **このファイルは、このタスクの「変わらない目的」の記録でもあります。**
> `00_TASK.md` が無いタスクでは、`01A_依頼内容.md` がその役割を兼ねます。
> 目的そのものが変わったときは、回を重ねずに**新しいタスクフォルダ**を提案してください。

## 4. 作業して、成果物を出す

出力先は **2. で宣言したパス**です。ファイル名は次の形式にします。

```
NNB_内容を表す日本語名_YYYY-MM-DD.拡張子
        例: 01B_差出人名簿_2026-09-16.xlsx
```

`NN` は回次です。新規タスクの1回目なので **`01`** です。
**`B` は成果物の印**で、同じ回の依頼（`01A_依頼内容.md`）とすぐ上下に並びます。

**次の回の成果物は `02B_…` です。この回のファイル名で上書きしません**
（→ `継続タスク` スキル 4）。

- 1回で3つ以上出すときは、`<タスクフォルダ>\NNB_タイトル_YYYY-MM-DD\` にまとめます。
  **`NNA_依頼内容.md` は直下に残し、この「3つ」にも数えません**
- 抽出スクリプト・中間データ・バックアップは `<タスクフォルダ>\材料\` に入れます。
  **タスクフォルダの直下は「ユーザーが読むもの」だけにします**
- **これ以外の名前のフォルダを、タスクフォルダの中に作らないでください。**
  書き込みの制限で止まります

**Python スクリプトを書くときは、書き出し先のパスを必ず目視確認してください。**
`open(path, "w")` や `to_excel(path)` の path に、タスクフォルダ名が入っていますか。
**スクリプトが書くファイルは、書き込みの制限では止まりません。**

### 最初から「1つのファイルで直していきたい」と言われたとき — 育てるファイル

「何回か直しながら仕上げたい」「同じファイルを直していってほしい」と**ユーザーから**言われたときだけ、
成果物を **`00_[日本語名].拡張子`**（例: `00_議事録.md`）の1ファイルにします
（→ `CLAUDE.md`「出力と保存のルール」2 の「育てるファイル」）。**自分の判断でこの形にしないでください。**

- 名前に日付は付けません。`00_TASK.md`・`00_作業記録.md` とは別の名前にします
- **回の終わりに、仕上がったものを `材料\01B_[日本語名]_YYYY-MM-DD.拡張子` に `Copy-Item` で写します**
  （第1回の控え）。写し先にタスクフォルダ名が入っていることを確かめてください
- 5. の `## 毎回守ること` に、次の1行を書きます。**次の回は、この行を見て同じ形で続けます**

      - 議事録は `00_議事録.md` を直していく（第1回から。各回の控えは `材料\`）

## 5. 作業記録を作る — `00_作業記録.md`

`<タスクフォルダ>\00_作業記録.md` を**新しく作ります。**
**これを忘れると、次回「続き」ができません。**

```markdown
## いまの状況

第1回まで完了。最新の成果物は 01B_差出人名簿_2026-09-16.xlsx。次の指示待ち

## 毎回守ること

（今回ユーザーから出た指摘のうち、次回以降も有効なものを書く。無ければ「なし」）

## 経緯

### 第1回 2026-09-16
- 依頼: 差出人の一覧を xlsx で作成（詳細は `01A_依頼内容.md`）
- 見た資料: （パス。おおよそでよい）
- わかったこと:
- できなかった・見つからなかったこと: （無ければ「なし」）
- 成果物: 01B_差出人名簿_2026-09-16.xlsx
- 次にできること:
  1.
  2.
  3.
```

**「依頼」の欄は、1行の要約と `01A_依頼内容.md` への参照にします。**
中身をここに書き写さないでください。二重管理になり、必ず食い違います。

育てるファイルにした場合、「成果物」の欄と `## いまの状況` は次のように書きます。

    - 成果物: 00_議事録.md を作成（控え: 材料\01B_議事録_2026-09-16.md）

    第1回まで完了。最新の成果物は 00_議事録.md（育てるファイル）。次の指示待ち

2回目以降は `継続タスク` スキルがこのファイルに追記していきます。

## 6. 報告する

1. 今回やったこと（1〜2行）
2. **成果物のフルパス**（タスクフォルダ名まで書く。ユーザーが場所の誤りに即座に気づけるようにするため）
3. **次にできること（番号付き、2〜3個）**
4. 処理できなかったファイル、見つからなかった項目があればその旨

あわせて、**次回からの呼び方**を伝えてください。

> 次回からは「**差出人名簿 の続き**」と言っていただければ、ここから再開できます。

## 注意

- **`00_TASK.md` を作らないでください。** 書き込みの制限で止まります。**それが正しい動作です。**
  書き起こした `01A_依頼内容.md` を `00_TASK.md` にしたいと言われたら、
  **ユーザーにコピーしてもらってください。**
  人が「これを依頼として引き受ける」と決める行為だからです。
- **フォルダの改名・移動・削除をしないでください**（絶対遵守ルール4）。
  間違った名前で作ってしまったら、**自分で直そうとせず**、
  どこに何を作ったかを正確に報告して指示を仰ぎます。
- 2回目からは `継続タスク` スキルです。**新しいフォルダを作らないでください。**
  目的そのものが変わったときだけ、新しいタスクフォルダを提案します。
