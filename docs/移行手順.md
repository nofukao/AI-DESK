# 旧構成から AI-DESK 1.0.0 への移行手順

作成: 2026-09-14

旧構成（`<共有>\AI-DESK\<個人フォルダ>\<タスク名>\out\`）から、
新構成（`<インスタンス>\<タスク名>\out\`）へ乗り換える手順です。

---

## 方針 — いちばん安い移行から始める

**移行は、思っているより安く済みます。**

旧構成の `<共有>\AI-DESK\<個人フォルダ>\<タスク名>\out\` は、
**その個人フォルダに配布物を置くだけで、新構成に合致します。**

```
旧: <個人フォルダ>\<タスク名>\out\     ← カレント = 個人フォルダ
新: <インスタンス>\<タスク名>\out\     ← カレント = インスタンスのルート
```

**カレントディレクトリからの深さが同じ**です（→ `設計.md` 6）。
つまり、**タスクフォルダを1つも動かす必要がありません。**

置き場所を組み替えるかどうかは、**それとは独立に、後から決められます。**
まず「配布物を降ろすだけ」を先にやるのが、いちばんリスクの低い進め方です。

---

## 第1段階 — 既存の個人フォルダに、配布物を置く

**タスクフォルダは動かしません。**

### 1-1. 作業用のインスタンスを、いったん別の場所に作る

```powershell
cd C:\Users\<あなた>\repos\AI-DESK-DEV
.\bin\new-instance.ps1 -Dest "C:\Users\<あなた>\Desktop" -Name "AI-DESK-移行用"
```

> **なぜ直接置かないのか**
>
> `new-instance.ps1` は、**コピー先が既にあると中止します。** 上書き事故を防ぐためで、
> これは意図した仕様です。既存の個人フォルダ（タスクフォルダが入っている）へは、
> このスクリプトでは置けません。
>
> **一度きりの移行は、人の目で見ながら手でコピーします。** それが最も安全です。

### 1-2. `PROFILE.md` を書く

**作られた直後のインスタンスに `PROFILE.md` はありません。** 作り方は2つあります。

**方法A（勧め）: 対話で作る。** `AI-DESK-移行用` のフォルダで claude を起動し、
「**初期設定**」と言ってください。聞き取りながら AI が作ります。
そのあと 1-3 の読み取り範囲まで、続けて設定できます。

**方法B: 手で書く。** `PROFILE.example.md` をコピーして `PROFILE.md` にし、
中身を書き換えます（冒頭の `AI-DESK-PROFILE-EXAMPLE` の行は消してください）。

どちらの場合も、**旧 `CLAUDE.md` の「我が社の業務（前提知識）」の章が、そのまま材料になります。**
方法Aなら、その章を見ながら質問に答えるのがいちばん早いです。移すのは次の内容です。

| 旧 `CLAUDE.md` のどこ | `PROFILE.md` のどこ |
|---|---|
| 「本業」「すべてが〜の話とは限りません」 | 1. この組織について |
| 業務で使う言葉の説明 | 2. よく使う言葉とその意味 |
| 主な事業フォルダの表 | 3. 参照する主なフォルダ |
| 物件・部屋・ファイル名の表記の約束 | 4. 記号・命名の約束 |
| **旧パスの読み替えルール** | 5. 過去の環境変更と、古い記録の読み替え |
| 組織固有のスキル一覧 | 6. この組織固有のスキル |

**`PROFILE.md` は配布されず、git にも入りません。** 実在の情報を書いて構いません。
むしろ、**実在の情報を書く場所はここだけです。**

### 1-3. 読んでよいフォルダを決める（`.claude\settings.local.json`）

こちらも**作られた直後には存在しません。** `初期設定` の続きで作れます（方法A）。
手で書く場合は `.claude\settings.local.json.example` をコピーして名前から `.example` を外します。

```json
{
  "permissions": {
    "additionalDirectories": [
      "Z:/<業務フォルダ1>",
      "Z:/<業務フォルダ2>"
    ],
    "deny": [
      "Edit(//z/**)"
    ]
  }
}
```

- **区切りは `/`（スラッシュ）です。** `\` ではありません
- **範囲は狭いほど安全です。** 旧構成の `"Z:/"`（ドライブ全体）から絞ることを勧めます。
  ドライブ全体にすると、**検索が終わらなくなることがあります**
- **`deny` を必ず対で書いてください。** 読める場所は、書けてはいけない場所です。
  これが**「自動」モードでも資料フォルダを守る歯止め**になります。
  `deny` はドライブ単位で `Edit(//z/**)` と書きます。**`Edit(Z:/**)` と書くと効きません**
  （Windows のパスは照合の前に `/z/...` の形に直されるため）。
  ドライブ単位で書いておけば、`additionalDirectories` を足しても効き続けます

### 1-4. 中身を、既存の個人フォルダへコピーする

`AI-DESK-移行用\` の**中身**（フォルダ自体ではなく、中のファイル・フォルダ）を、
既存の個人フォルダへコピーします。エクスプローラーの**コピー → 貼り付け**で構いません。

```
コピーするもの（AI-DESK-移行用\ の中身すべて）
    CLAUDE.md / PROFILE.md / PROFILE.example.md / GEMINI.md / README.md
    .ai-desk\        （VERSION と source.txt）
    .claude\         （settings.json / settings.local.json / skills\）
    bin\
    task_template\

コピー先
    <共有>\AI-DESK\<個人フォルダ>\        ← 既存。タスクフォルダはそのまま
```

**注意点**

- **`.claude` や `.ai-desk` は隠しフォルダです。** エクスプローラーの
  「表示」→「隠しファイル」をオンにしてください。**コピー漏れがあると動きません**
- **既存の `GEMINI.md` は上書きされます。** 旧版は「`type ..\CLAUDE.md` しろ」と
  書かれており、新構成では誤りになるため、**上書きが正解**です
- **既存の `.claude\settings.json` も上書きされます。** 新旧で `allow` / `deny` は同じで、
  `additionalDirectories` が空になるだけです（読み取り範囲は `settings.local.json` へ移りました）
- **タスクフォルダには一切触れません。** 同名のものが無いためです

### 1-5. `source.txt` を直す

`.ai-desk\source.txt` には、`AI-DESK-移行用` を作ったときのコピー元が書かれています。
**配布原本を社内に置いたら、そのパスに書き換えてください。**

```
<社内の配布原本>\AI-DESK
```

ここが正しいと、`疎通確認` が**版ずれを自動で知らせます**。
書き換えなくても動きますが、版ずれの検出が効きません。

## 第2段階 — 動作確認

移した個人フォルダ（＝これがインスタンスになりました）で確認します。

### 2-1. そのフォルダで claude を起動する

```powershell
cd "<共有>\AI-DESK\<個人フォルダ>"
claude
```

**「このフォルダを信頼しますか」が出たら、必ず承諾してください。**
フォルダの中身が変わったため、再度出ることがあります。
ここで断ると設定がすべて無視され、資料を一切読めません。

### 2-2. 疎通確認

```
疎通確認
```

次が報告されれば正常です。

- **インスタンスのフルパスと版番号**（`1.0.0`）
- 配布元との版の比較（`source.txt` を直していなければ「確認できませんでした」でよい）
- `PROFILE.md` がある
- 読み取り範囲の一覧と、**実際に1つ読めたこと**
- Python が使えること
- **`<タスク>\out\` に書けること／ルート直下 `out\` が拒否されること**

### 2-3. 既存タスクの「続き」が動くか

**これが本番の確認です。** 既存のタスクフォルダを1つ選び、こう頼みます。

```
<タスク名> の続き
```

`<タスク名>\out\00_作業記録.md` を読んで再開すれば成功です。

> **既存の `out\00_作業記録.md` は、そのまま使えます。**
> `継続タスク` スキルが読む場所（`<タスクフォルダ>\out\`）は、**新旧で変わっていません。**
> 書き換える必要はありません。

## 第3段階（任意）— 置き場所を組み替える

**やらなくても構いません。** 必要が出てから決めてください。

個人名の階層が不要になったので、たとえばこう置けます。

```
<共有>\個人\<名前>\AI-DESK        ← 通常業務用
<共有>\個人\<名前>\AI-DESK2       ← 別案件用
C:\Users\<あなた>\AI-DESK          ← NAS を使わないとき
<共有>\共有\<部署>\AI-DESK        ← 共同作業用
```

**フォルダごと移動すれば動きます**（`.ai-desk\VERSION` が目印なので、名前も自由です）。
ただし次の2点に注意してください。

- **移動すると「このフォルダを信頼しますか」が再度出ます。** 承諾が必要です
- **claude の履歴はパス単位で保存されます。** 移動すると過去の会話履歴が見えなくなります

---

## 必ず守ること

### 1. 過去の記録に残る古いパス表記は、書き換えない

過去の作業記録・成果物・`task.md` に残っている古いパス表記（
`<旧ドライブ>\<旧フォルダ>\…` や `<個人フォルダ>\<タスク名>\…` の形）は、
**そのまま残してください。** 当時の記録だからです。

読むときに現在の場所へ読み替えます。**読み替え表は `PROFILE.md` に1行足す形**で対応します。
以前フォルダ名を変えたときと同じやり方です。

**書き換えて回ると、「当時どこに何を出したか」が分からなくなります。**

### 2. 現行環境は、新構成の確認が済むまでそのまま動かす

**移行中も、これまでどおり使えます。** 第1段階は「配布物を置くだけ」で、
タスクフォルダにも成果物にも触れません。

問題が起きたら、**置いたファイルを元に戻せば旧構成に戻ります**
（旧 `GEMINI.md` と旧 `.claude\settings.json` は、上書きする前にコピーを取っておいてください）。

### 3. 既存の `out\00_作業記録.md` は、そのまま使える

`継続タスク` スキルが読む場所は変わっていません。移行のために書き換える必要はありません。

## 移行後に残る宿題

旧構成から持ち越すもの、新構成で解消したものの一覧です。

| 事項 | 新構成での扱い |
|---|---|
| claude の履歴がネットワークドライブで空になる問題（ジャンクションで回避） | **残る。** PC ごと・フォルダごとに対処が必要。ただし**インスタンスをローカルに置けるようになった**ぶん、逃げ道は増えた |
| 旧作業の残骸スクリプトに残る旧パス1か所 | **残る。** 移行では触らない（記録として残す方針） |
| 別サーバーに残る旧世代の作業場の扱い | **残る。** 今回の対象外 |
| 信頼済みフォルダの大文字小文字の重複登録 | **残る。** claude 側の事情 |
| 業務フォルダに残るロックファイル（`~$*.xlsx`）の削除 | **残る。** AI は削除できません（絶対遵守ルール4）。人の作業 |
| 旧タスクの `out\` 直下のファイル整理 | **残る。** 移動は AI が行えません。人の作業 |
| 「`Readme.md` をコピーせず原本参照にする」構造的対策 | **部分的に解決。** 原本参照にはなっていないが、`update-instance.ps1` で**配り直せる経路**ができた |
| 業務フォルダを共有ディスク側で読み取り専用にできるか | **残る（必要性は下がった）。** `settings.local.json` で読み取り範囲を絞れるようになったため |
| 個人フォルダテンプレート側への `GEMINI.md` 反映漏れ | **解消。** 個人フォルダテンプレートが廃止され、`GEMINI.md` は配布物に1つだけになった |
| Antigravity で再実行し、出力先の対策が効いたか実地確認 | **残る。むしろ価値が上がった。** 新構成では参照先が `type CLAUDE.md` に単純化されたので、**新しい `GEMINI.md` での検証が必要** |

## 受け入れテストのチェックリスト

**新しいインスタンスを1つ作って確かめます。** 消してよい場所に作ってください。

```powershell
cd C:\Users\<あなた>\repos\AI-DESK-DEV
.\bin\new-instance.ps1 -Dest "C:\Users\<あなた>\Desktop" -Name "AI-DESK-TEST"
```

| # | 確認すること | 期待 | 確かめ方 |
|---|---|---|---|
| 1 | `.git` が無い | **無い** | `Get-ChildItem <TEST> -Recurse -Force -Directory -Filter .git` が空 |
| 2 | `.ai-desk\VERSION` がある | 配布物と同じ版 | `Get-Content <TEST>\.ai-desk\VERSION` |
| 3 | `.ai-desk\source.txt` がある | コピー元のパス | `Get-Content <TEST>\.ai-desk\source.txt` |
| 4 | `PROFILE.md` が**無い** | **無い**（記入例を置かないため） | `Test-Path <TEST>\PROFILE.md` が `False` |
| 5 | 配布物に実在の固有名詞が無い | **1件も無い** | 下の「5 の確かめ方」 |
| 6 | `.ps1` が BOM 付き UTF-8 | 全ファイル | 下の「6 の確かめ方」 |
| 7 | テストタスクの `out\` に書ける | **書ける** | `<TEST>` で claude を起動し、`疎通確認`（8-1） |
| 8 | ルート直下 `out\` は拒否される | **`deny` で拒否される** | 同上（8-2） |
| 9 | インスタンス外への書き込み | **「自動」モードでは通ります** | 下の注意を読むこと |
| 10 | `.ps1` でパスを文字列連結していない | `Join-Path` を使用 | `Select-String -Path bin\*.ps1 -Pattern '\$\w+\\'` が空 |
| 11 | `CLAUDE.md` の OS 依存記述が1章に集まっている | 「実行環境について（Windows）」の中だけ | 目視。`powershell` `cp932` `WindowsApps` `260` を検索 |
| 12 | `.gitattributes` に `*.sh text eol=lf` がある | ある | `Select-String -Path .gitattributes -Pattern 'sh text eol=lf'` |
| 13 | `初期設定` が動く | 対話で `PROFILE.md` が作られる | `<TEST>` で `初期設定` と言う |
| 14 | 読み取り範囲と `deny` が対になっている | 対になっている | `疎通確認`（6-2） |
| 15 | 資料フォルダに書けない | **`deny` で拒否される** | `疎通確認` のあと、読み取り範囲のどこかにファイルを作らせてみる |

**7・8・13・14・15 は、`AI-DESK-TEST` のフォルダで claude を起動しないと確かめられません。**
権限は、そのフォルダの `.claude\settings.json` が読み込まれて初めて効くためです。
**初回の「このフォルダを信頼しますか」に承諾してから**実施してください。

> **7 が通らない場合は、すぐに止めてください。** ルート直下の `out` を塞ぐ `deny`（`Edit(/out/**)`）が、
> タスクフォルダの `out` にまで当たっている可能性があります。
> そうなると、この AI-DESK は**何も出力できません。**

> **9 について（正直に書いておきます）**
>
> この AI-DESK は既定で「自動」モードで動くため、**`deny` に挙げていない場所への書き込みは、
> 確認なしで通ります。** インスタンスの外（デスクトップなど）は事前に列挙できないため、
> `deny` で塞げません。**ここは規則だけが歯止めです。**
>
> 守られているのは「**資料フォルダに書かせない**」（15）と
> 「**ルート直下 `out\` を作らせない**」（8）で、こちらは `deny` により
> モードに関係なく機械的に拒否されます。
> **ただし、AI が直接書き込む場合に限ります。** Python などのスクリプトが自分で書き出すファイルは、
> `deny` では止まりません。詳しくは `設計.md` の 10 を読んでください。

### 5 の確かめ方

配布物全体を検索し、実在の個人名・会社名・取引先名・物件番号が残っていないか確認します。
**見つかったら、架空の例に置き換えてください。**

```powershell
Select-String -Path "<TEST>\*","<TEST>\**\*" -Pattern "<実在の名前1>","<実在の名前2>"
```

開発リポジトリ側では、次で確認できます（git が追跡している全ファイルが対象）。

```powershell
git grep -n "<実在の名前>"
```

### 6 の確かめ方

```powershell
Get-ChildItem "<TEST>" -Recurse -Filter *.ps1 | ForEach-Object {
    $bytes = [System.IO.File]::ReadAllBytes($_.FullName)
    $bom = ($bytes[0] -eq 0xEF) -and ($bytes[1] -eq 0xBB) -and ($bytes[2] -eq 0xBF)
    "{0}  BOM={1}" -f $_.Name, $bom
}
```

**確認が済んだら、`AI-DESK-TEST` は手で削除して構いません。**
**AI には消させないでください**（絶対遵守ルール4）。
